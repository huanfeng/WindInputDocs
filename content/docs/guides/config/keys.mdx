<Callout type="warn" title="高级主题">
普通用户在[设置工具](/docs/settings)的"快捷键"页即可完成全部按键设置，修改即时生效。本页面向手动编辑 `config.toml` 的用户，逐项列出 `[keys]` 域的类型、可选值与默认值。
</Callout>

`[keys]` 域收纳输入法的**全部按键绑定**：中英切换键、引擎切换与状态切换快捷键、候选选择/翻页/高亮/以词定字键组、功能快捷键，以及全局热键。该域是**扁平结构**——除无效按键策略下沉到 `[keys.overflow]` 一层子表外，其余字段都直接挂在 `[keys]` 下。

字段分两类：

- **热键字符串**（如 `switch_engine`）：单个组合键，格式见下方"[热键字符串格式](#热键字符串格式)"。
- **键组数组**（如 `page_keys`）：值不是键名而是**键组常量**（一个常量代表一对物理按键），可多选、以数组给出。每个这类字段下方都附一张"可选值 → 物理按键"对照表。

## 热键字符串格式

热键字符串由**修饰键 + `+` + 主键**组成，大小写不敏感、可含空格。

- 修饰键：`ctrl`（= `control`）、`shift`、`alt`、`win`（= `super`）。
- 主键：字母 `a`–`z`；数字 `0`–`9`；功能键 `f1`–`f12`；`space` / `enter` / `tab` / `esc` / `backspace` / `delete` / `home` / `end` / `pageup` / `pagedown` / 方向键 `up`/`down`/`left`/`right`；标点符号可用符号本身或英文名，如 `.`（= `period`）、`,`（= `comma`）、`;`（= `semicolon`）、`'`（= `quote`）、`/`（= `slash`）、`\`（= `backslash`）、`[`（= `lbracket`）、`]`（= `rbracket`）、`-`（= `minus`）、`=`（= `equal`）、`` ` ``（= `grave`）。
- **空串或 `none`** 表示不绑定该功能。
- 只允许一个主键；写多个主键会被判为无效并忽略。

<Callout type="info" title="TOML 里的反斜杠">
`toggle_toolbar` 默认值含反斜杠，在 TOML 中需用**单引号**字符串写成 `'ctrl+shift+\'`，否则双引号里的 `\` 会被当作转义符。
</Callout>

## 中英切换

```toml
[keys]
toggle_mode_keys = ["lshift", "rshift"]  # 中英切换键（键松开时触发）
commit_on_switch = true                  # 切到英文时是否上屏未完成的组合
```

| 键 | 类型 | 可选值 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `toggle_mode_keys` | 字符串数组 | `lshift` / `rshift` / `lctrl` / `rctrl` / `capslock` | `["lshift", "rshift"]` | 单击并松开这些修饰键即切换中/英文模式。可多选，空数组=禁用点击切换 |
| `commit_on_switch` | 布尔 | `true` / `false` | `true` | 从中文切到英文时若有未上屏的组合：`true`=上屏原始编码，`false`=直接丢弃 |

`toggle_mode_keys` 可选值对照：

| 可选值 | 物理按键 |
| --- | --- |
| `lshift` | 左 Shift |
| `rshift` | 右 Shift |
| `lctrl` | 左 Ctrl |
| `rctrl` | 右 Ctrl |
| `capslock` | Caps Lock |

## 状态切换快捷键

```toml
[keys]
switch_engine = "ctrl+shift+e"    # 循环切换输入方案
toggle_full_width = "shift+space" # 全角/半角切换
toggle_punct = "ctrl+."           # 中文/英文标点切换
toggle_s2t = "ctrl+shift+j"       # 简体/繁体输出切换
```

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `switch_engine` | 热键字符串 | `ctrl+shift+e` | 在 `[schema].available` 列表内循环切换当前方案 |
| `toggle_full_width` | 热键字符串 | `shift+space` | 切换全角/半角字符输出 |
| `toggle_punct` | 热键字符串 | `ctrl+.` | 切换中文/英文标点（仅中文模式下生效） |
| `toggle_s2t` | 热键字符串 | `ctrl+shift+j` | 切换简体/繁体输出（仅中文模式下生效） |

### 方案直达热键 [#schema-hotkeys]

`switch_engine` 是循环切换，方案多了就要按好几次。给单个方案绑一个键，按下直接切过去：

```toml
[keys.key_actions]
"ctrl+shift+w" = "switch_schema:wubi86"   # 单向：切过去就完了
"ctrl+shift+n" = "toggle_schema:english"  # 往返：再按一次回到原来那个方案
```

设置工具里的位置：**方案 → 输入方案 → 选中方案 → 设置 → 进入方式 → 直达热键**（写的是 `switch_schema:`）。

行为与 `switch_engine` 完全一致——同样遵循「切换时是否上屏」，同样把选择持久化到 `schema.active`。**两种模式下都生效**，这一点和其它中文态专属的快捷键不同：切到英文方案之后，还得能按键切回来。

指向不存在或未启用方案的条目会被安静忽略，不影响其它绑定；目标方案正在后台预热时提示「准备中…」并保持当前方案不变。

<Callout type="warn" title="schema_hotkeys 已废弃，需手改">
旧写法 `[keys] schema_hotkeys = { wubi86 = "ctrl+shift+w" }` **不再生效，且不会自动迁移**。残留的旧段会在启动日志里告警一次，请改写成上面 `key_actions` 的形式，或在设置工具「方案 → 选中方案 → 设置 → 进入方式」里重配一次。

合并的原因是两处配的本是同一件事、只差单向/往返，却编译进同一张热键表：同一个键两处都配时后者**静默失效**；而旧表不校验键形态，在里面写一个单字符键会让那个字符再也打不出来。
</Callout>

<Callout type="info" title="与临时模式的区别">
`key_actions` 里 `special:` / `mix:` / `temp_pinyin` 那批动词进的是**临时模式**——打完一段自动退回原方案。`switch_schema:` 与 `toggle_schema:` 是**换方案**：前者切过去就完了，后者再按一次回到你原来那个方案。要「临时打几个字符就回来」用临时模式，要「切过去待一会儿」用换方案。
</Callout>

<Callout type="warn" title="switch_schema 只能写在全局">
方案文件的 `[key_actions]` 按**活跃方案**查表。单向切走之后，目标方案没有这条绑定，那个键就再也按不动了。方案级要绑切换请用 `toggle_schema:`——它的回程由运行时来源兜底，不要求目标方案配一个对称的键。
</Callout>

### 按键功能表（key_actions）<Since v="0.115" /> [#key-actions]

上面那批热键是「一个功能一个字段」。`key_actions` 是通用的「**键 → 干什么**」表：左边任意键名，右边一个动词。引导键、临时模式入口、方案往返键都统一住在这里。

```toml
[keys.key_actions]
backslash = "special:quick_symbols"       # \ 进快符
backtick = "temp_pinyin"                  # ` 进临时拼音
semicolon = "mix:quick_mix"               # ; 进快捷输入
"ctrl+shift+u" = "special:quick_symbols"  # 快符的直达热键
rshift = "toggle_schema:english"          # 轻敲右 Shift 切英文方案，再敲回来
```

动词值域：

| 动词 | 含义 |
| --- | --- |
| `temp_pinyin` / `temp_english` | 进临时拼音 / 临时英文 |
| `aux_code` <Since v="0.118" /> | 进[辅助码](/docs/settings/schema/pinyin)筛选：对已出的拼音候选按字形二次过滤。需已开启辅助码且当前有候选 |
| `mix:<实例id>` | 进指定融合模式（`mix:quick_mix` = 内置[快捷输入](/docs/settings/input/quick-input)） |
| `special:<方案id>` | 进指定[引导键特殊模式](/docs/guides/special-modes)——方案须已声明 `[overlay]` 段 |
| `toggle_schema:<方案id>` | 切到指定方案，**再按一次回到来源**（往返，不要求目标方案配对称的绑定） |
| `switch_schema:<方案id>` | 切到指定方案，**单向**（原 `keys.schema_hotkeys` 的语义；只能写在全局那份表里） |
| `toggle_mode`、`switch_engine`、`toggle_punct`、`toggle_s2t`、`toggle_full_width`、`toggle_toolbar`、`open_settings`、`take_screenshot` | 与同名快捷键完全一样的状态切换 |
| `none` | 显式什么都不做，用于在方案级覆盖里**关掉**某个全局绑定 |

写错的动词会被**整条丢弃**并在日志里告警，不会静默变成别的功能。

#### 键的形态决定走哪条通路

同一张表里的条目按**键的形态**自动分流，不由动词决定，也不需要你指定：

| 键的形态 | 通路 | 为什么 |
| --- | --- | --- |
| 组合键（`ctrl+shift+u`） | 热键 | 不与输入争键，可全局拦截 |
| 纯修饰键（`rshift`、`lctrl`） | 松开时的**轻敲**判定 | 按下时不能吃——宿主还要看到这个修饰键 |
| 单个有字符的键（`backslash`、`;`） | 引导键链 | 排在中英文分水岭之后，英文模式下照常出字符 |

<Callout type="warn" title="组合键只认三类动词">
走热键通路的**组合键**（`ctrl+shift+u` 这种）只接受 `toggle_schema:`、`switch_schema:`、`special:` 三类动词。其余动词要么需要操作当前的编码与候选、要么已经有自己的[功能快捷键](#功能快捷键)字段，配在组合键上会被整条丢弃并在日志里告警。

设置界面的按键选择对话框据此过滤：选了组合键，功能列表就只剩这三类。
</Callout>

<Callout type="warn" title="切方案 / 切中英文只能绑修饰键">
`toggle_mode`、`switch_engine`、`toggle_schema:*`、`switch_schema:*` 这几类**只接受修饰键**（组合键当然也行），绑到单个有字符的键上会被拒绝。

理由是单程票问题：有字符的键走引导键链，而那条链在英文模式分水岭之后、英文态根本到不了。用 `\` 切去英文方案之后，`\` 就只会打出反斜杠，再也切不回来。这三个动词恰恰是「从英文态出来」的手段，所以必须绑在英文态也能生效的修饰键上。
</Callout>

#### 方案级覆盖

方案文件（或 `schema_overrides\<方案ID>.toml`）也能写一份 `[key_actions]`，只在该方案作当前方案时生效，**逐键覆盖**全局那份：

```toml
# wubi86.schema.toml
[key_actions]
z = "temp_pinyin"       # 五笔里借 z 打拼音
backslash = "none"      # 本方案关掉全局配的 \ 引导键
```

**字母键只能按方案配**，不能写进全局表：字母天然是编码键，能不能借用取决于这张码表里它是不是死码。全局表里配字母就成了无条件抢键，那个字母在所有方案里都打不出编码了。

要在某个方案里**关掉**一个全局绑定，写显式的 `"none"`。覆盖是深合并，只能新增或改写——从覆盖文件里删掉一行是删不掉全局那条的。

<Callout type="warn" title="字母键让位给编码，所以别用 z 进特殊模式">
绑了功能的字母键，若在当前码表里**是活码**（这个字母开头有真实编码或短语），按下时会**让位给正常输入**，不进模式。这是刻意的：编码优先。

`z` 尤其要注意——出厂词库自带 37 条 `zz` 开头的标点短语（`zzbd`、`zzsz` 等），所以**在任何方案里 z 都是活码**，按下去总是先当编码。

之后能被捞回来的只有三个动词：`temp_pinyin`、`temp_english`、`mix:<id>`。继续打出该码表里查不到的编码时（如 `znihao`），输入法会把 `z` 夺回来转交模式，而 `zzbd` 这类真实短语照常工作。

`special:<方案id>` **没有**这条回捞通路——特殊模式的码表是作者设计的短码，去掉 `z` 之后的残余多半查不到，且它常开「进入即展示候选」，价值恰恰在按下那一刻。所以特殊模式请用 `\`、`` ` `` 这类在码表里不产出编码的符号键。
</Callout>

### 会话态按键功能表（session_actions） <Since v="0.115" /> [#session-actions]

`key_actions` 给一个键指定**功能**（进模式、切方案、切状态）；`session_actions` 管的是「**正在打字**（有编码或候选）时这个键干什么」。两张表，同一个键在两处可以是两个动作——Tab 打字时翻页、没在打字时仍是宿主的制表符。

<Callout type="info" title="分野不是「空闲时 vs 输入中」">
`key_actions` 的三条通路在**打字中同样触发**：组合键走热键、修饰键走松开轻敲、有字符的键先把已有编码上屏再执行。「轻敲右 Shift 切中英文」正是打字中途最常用的一个。

真正的差别是：`session_actions` **只**在有编码或候选时生效，且管的是对这段输入本身的操作（翻页、选词、放弃）。
</Callout>

```toml
[keys]
session_actions = {}   # 出厂为空；例：{ tab = "page_next", "shift+tab" = "page_prev" }
```

| 键 | 类型 | 可选值 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `session_actions` | 表（键名 → 动词） | 见下 | `{}` | 打字期间的「键 → 干什么」表，只存你显式配的键 |

- **键名**：`tab` / `shift+tab` / `capslock` / `pageup` / `pagedown` / `up` / `down` / `left` / `right` / `home` / `end`，以及符号键 `minus`、`equal`、`lbracket`、`rbracket`、`comma`、`period`、`semicolon`、`quote` 等；字母只收 `z` <Since v="0.118" />。只认 `shift+` 一种前缀；带 Ctrl / Alt 的组合键请写在上面的 `key_actions` 里。
- **动词**：`page_prev` / `page_next`（翻页）、`highlight_up` / `highlight_down`（高亮移动）、`cancel`（放弃当前输入，等同 Esc；别名 `clear`）、`none`（在打字态禁用该键）、`select_candidate:N`（选中当前页第 N 个候选，N 从 1 起，`2` 即次选键）、`select_char:N`（以词定字，取高亮候选词的第 N 个字）。两个 N 的取值范围都是 **1–9**。此外还有 `aux_code` <Since v="0.118" />（进[辅助码](/docs/settings/schema/pinyin#aux-code)筛选）——它同时也是 `key_actions` 的动词，两处通向同一个功能，差别只在**哪些键名解析得出来**：本表认得 `tab` / `pagedown` / 方向键，`key_actions` 只认符号键、字母 `z` 与四个修饰键。

本表与下面的 `page_keys` / `highlight_keys` / `select_key_groups` / `select_char_keys` 各自独立保存，**运行时**才合并（本表写了的键优先）——改一处不会动到另一处。出厂默认留在那四项里，这样把它们清成 `[]` 就真的能关掉对应功能。撞键时按消费顺序裁决：以词定字 > 翻页 / 高亮 > 二三候选。

<Callout type="warn" title="把 z 配成功能键的代价">
字母里**只有 `z`** 能写进本表——其余字母在任何码表里几乎都是活码前缀，配了等于把那个字母在该方案里废掉。

配了 `z` 之后：**空缓冲按 `z` 不受影响**，照常起头打编码；被夺走的只有「已经出候选、再按一次 `z`」那一下。所以五笔那 37 条 `zz` 开头的标点短语（`zzbd`、`zzsz`）就打不出来了——它们正需要这一下。

要的是「空闲时按 z 进某个模式」而不是打字中的功能，请写 [`key_actions`](#key-actions)（或方案文件的 `z_key_action`），那是另一张表。
</Callout>

<Callout type="warn" title="capslock 会安装全局键盘钩子">
Windows 的大小写锁定状态在输入法拿到按键之前就已翻转，常规通路压不住。本表**或任何一个方案**的 `[session_actions]` 配了 `capslock`，程序就会安装一个全局键盘钩子，在系统改状态之前拦下它（打字时才拦，空闲时 CapsLock 照常切大小写）；**哪儿都没配 capslock 就完全不装这个钩子**。副作用：极少数安全软件会对全局键盘钩子告警。

之所以「任何一个方案配了就装」而不是「当前方案配了才装」：钩子是进程级资源，按当前方案装卸会让每次切方案都装一次、卸一次，症状是切完方案 CapsLock 时灵时不灵。方案里把它写成 `"none"`（显式禁用）则不计入——那种情况下不会为它装钩子。
</Callout>

#### 方案级覆盖 <Since v="0.118" /> [#schema-session-actions]

方案文件（或 `schema_overrides\<方案ID>.toml`）也能写一份 `[session_actions]`，只在该方案作当前方案时生效，**逐键覆盖**全局那份：

```toml
# 某个特殊语系的方案
[session_actions]
lbracket = "page_prev"    # 本方案改用方括号翻页
rbracket = "page_next"
tab = "none"              # 本方案关掉全局配的 Tab
```

与 `[key_actions]` 的覆盖规则完全一致：深合并，只能新增或改写。要在某个方案里**关掉**一个全局绑定，写显式的 `"none"`——从覆盖文件里删掉那一行只是回到继承全局，不是禁用。

方案没写的键照常继承全局那份（含 `page_keys` 等四项折算出来的默认值）。

## 功能快捷键

```toml
[keys]
toggle_toolbar = 'ctrl+shift+\'       # 显示/隐藏工具栏
open_settings = "ctrl+shift+]"        # 打开设置工具
add_word = "ctrl+equal"               # 就地加词（从当前组合造词）
open_add_word_dialog = "ctrl+shift+equal" # 打开加词小窗
activate_ime = "ctrl+shift+["         # 切换到本输入法（系统级）
```

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `toggle_toolbar` | 热键字符串 | `ctrl+shift+\` | 显示/隐藏常驻工具栏 |
| `open_settings` | 热键字符串 | `ctrl+shift+]` | 打开设置工具窗口 |
| `add_word` | 热键字符串 | `ctrl+equal` | 就地加词，仅中文模式生效。该键额外走系统级全局拦截，规避 QQNT / Tabby 等宿主的加速键双处理 |
| `open_add_word_dialog` | 热键字符串 | `ctrl+shift+equal` | 打开独立加词小窗，仅中文模式生效，同样走全局拦截 |
| `activate_ime` | 热键字符串 | `ctrl+shift+[` | 切换到本输入法。经 Windows `DirectSwitchHotkeys` 注册表交由系统 `ctfmon` 原生处理（per-app 切换），**不经引擎按键分发** |

<Callout type="warn" title="take_screenshot（隐藏字段）">
`keys.take_screenshot`（默认 `ctrl+shift+f11`）是有效但**未在设置界面暴露**的字段，也不写入随程序分发的 `data\config.toml`——它只有代码默认值。按下时触发截图（`trigger_screenshot`），并可作为全局热键动作。需自定义时只能手动写入 `config.toml`：

```toml
[keys]
take_screenshot = "ctrl+shift+f11"  # 隐藏字段，设置界面无对应项
```
</Callout>

## 候选置顶与删除

```toml
[keys]
pin_candidate = "ctrl+number"           # 置顶候选（Ctrl+数字）
delete_candidate = "ctrl+shift+number"  # 删除候选（Ctrl+Shift+数字）
```

| 键 | 类型 | 可选值 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `pin_candidate` | 热键字符串（模板） | `ctrl+number` / `ctrl+shift+number` | `ctrl+number` | 对当前页第 N 个候选执行置顶。`number` 占位符展开为数字键 0–9 |
| `delete_candidate` | 热键字符串（模板） | `ctrl+number` / `ctrl+shift+number` | `ctrl+shift+number` | 对当前页第 N 个候选执行删词。`number` 占位符展开为数字键 0–9 |

<Callout type="info" title="这两项只认固定模板">
`pin_candidate` / `delete_candidate` 只识别 `ctrl+number` 与 `ctrl+shift+number` 两种写法（`number` 代表数字键组）；填其它值会被判为无效并忽略，等同于不绑定。
</Callout>

## 候选选择键组

```toml
[keys]
select_key_groups = ["semicolon_quote"]  # 次选/三选键组
```

| 键 | 类型 | 可选值 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `select_key_groups` | 字符串数组 | `semicolon_quote` / `comma_period` / `lrshift` / `lrctrl` | `["semicolon_quote"]` | 除数字键外的候选快捷选择键组：每组第 1 键选第 2 个候选、第 2 键选第 3 个候选。可多选，空数组=仅用数字键选词 |

`select_key_groups` 可选值对照：

| 可选值 | 第 2 候选键 | 第 3 候选键 |
| --- | --- | --- |
| `semicolon_quote` | `;` | `'` |
| `comma_period` | `,` | `.` |
| `lrshift` | 左 Shift | 右 Shift |
| `lrctrl` | 左 Ctrl | 右 Ctrl |

<Callout type="info">
  修饰键组（`lrshift` / `lrctrl`）在**松开**时才选词，且只认「轻敲」——按住超过 500 毫秒、
  或按下期间碰了别的键，都不算选词。这样 `Ctrl+A`、`Shift+字母` 这类组合才不会被误判成选候选。

  如果同一个键同时配成了中英文切换键（`toggle_mode_keys`），裁决是：**有候选时选词，
  无候选时切中英文**；候选数量不足以命中该位次时吞掉该键，既不上屏也不切换
  （修饰键没有对应字符，故不套用 `[keys.overflow]` 的策略）。
</Callout>

## 以词定字

```toml

```

| 键 | 类型 | 可选值 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `select_char_keys` | 字符串数组 | `comma_period` / `minus_equal` / `brackets` | `[]` | 用成对标点键从当前高亮候选词中**逐字上屏**：第 1 键取第 1 字、第 2 键取第 2 字。空数组=禁用。词长不足时按 `[keys.overflow].select_char_key` 策略处理 |

| `brackets` | `[` | `]` |

## 全局热键

```toml
[keys]
global_hotkeys = []  # 提升为系统级全局热键的动作名列表
```

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `global_hotkeys` | 字符串数组 | `[]` | 列出的**动作名**将经 Win32 `RegisterHotKey` 注册为系统级热键，使其在任意应用中生效。填的是动作名而非键值，键值仍取各功能字段自身的绑定 |

`global_hotkeys` 支持的动作名：

| 动作名 | 对应功能 |
| --- | --- |
| `switch_engine` | 切换方案 |
| `toggle_full_width` | 全/半角切换 |
| `toggle_punct` | 中/英标点切换 |
| `toggle_toolbar` | 显示/隐藏工具栏 |
| `open_settings` | 打开设置 |
| `take_screenshot` | 截图 |
| `toggle_s2t` | 简/繁切换 |

<Callout type="warn" title="不支持的动作会被忽略">
只有上表 7 个动作可放进 `global_hotkeys`；填写其它名字（含 `add_word` / `activate_ime` 等）会被判为不支持并忽略。其中 `activate_ime` 另有专属系统级通道（`DirectSwitchHotkeys` 注册表），无需也不能列在此处；`add_word` 需要当前组合上下文，不参与全局注册。
</Callout>

## 无效按键策略（keys.overflow）

当按下选择/翻页/以词定字类按键，但**候选数量或词长不足以命中目标位次**时的处理方式。三项共用同一套枚举。

```toml
[keys.overflow]
number_key = "ignore"       # 数字键超出当前页候选数量时
select_key = "ignore"       # 次选/三选键候选不足时
select_char_key = "ignore"  # 以词定字键候选词长度不足时
```

| 键 | 类型 | 可选值 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `number_key` | 枚举 | `ignore` / `commit` / `commit_and_input` | `ignore` | 数字键位次超出当前页候选数量时的行为 |
| `select_key` | 枚举 | `ignore` / `commit` / `commit_and_input` | `ignore` | 次选/三选键（见 `select_key_groups`）候选不足时的行为 |
| `select_char_key` | 枚举 | `ignore` / `commit` / `commit_and_input` | `ignore` | 以词定字键（见 `select_char_keys`）候选词长度不足时的行为 |

枚举取值行为：

| 取值 | 行为 |
| --- | --- |
| `ignore` | 吞掉该键，不做任何操作（默认） |
| `commit` | 上屏当前高亮的候选 |
| `commit_and_input` | 上屏当前高亮候选，并把该按键对应的字符追加输入 |
