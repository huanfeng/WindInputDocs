**方案 → 全局方案配置 → 英文方案配置** <Since v="0.114" />。英文（方案 ID `english`）是一个**普通的可切换方案**，和五笔、拼音一样出现在方案列表里：启用后用循环键或直达热键切过去，输入字母出英文候选（词库补全）。

对应配置段是 `config.toml` 的 `[schema.english]`，完整键名与默认值见[方案与引擎配置](/docs/guides/config/schema#english)。

<Callout type="info" title="它和「临时英文」不是一回事">
- **英文方案**——切过去打一整段英文，再切回中文。走常规输入路径，出词库候选，有自己的用户词库与词频
- **[临时英文](/docs/settings/input/temp-modes#临时英文)**——中文输入中途插几个英文单词，打完自动回中文

两者**共用词库与学习数据**：本页的[词频调整](#词频调整)与[自动加空格](#上屏后自动加空格)从 0.118 起同时管辖临时英文，临英里选过的词切到英文方案照样排在前面，反之亦然。

各管各的只有两处：临英独有的按键语义（符号数字入码、空格作输入）在临英那边；[候选面那两项](#candidate-face)（原文候选、大小写变形）**两侧各有一份、互不影响**。
</Callout>

## 怎么用上它

英文方案就在[方案页](/docs/settings/schema)的列表里（**不需要**勾「显示特殊方案」，它不是特殊方案），默认未启用。两种用法：

- 把它加入已启用列表，用 `Ctrl + Shift + E` 循环切换
- 或者**不启用**，只给它配一个[直达热键](/docs/settings/schema#schema-hotkey)——按热键切过去打一段，再按循环键或另一个热键切回来。这样它不占循环位置

首次切过去时会现加载词库，可能有短暂停顿，之后就缓存住了。

## 词频调整

| 选项 | 说明 | 出厂 |
| --- | --- | --- |
| 启用词频调整 | 总开关 | 关 |
| 调频策略 | 位次渐进 / 一次到顶 / 逐次提升 | 位次渐进 |
| 补全词参与调频 | 前缀补全候选是否参与提升。**仅「位次渐进」下可用** | 全部 |
| 热度衰减半衰期 | 使用记录衰减到一半的小时数，`0` = 内置 72 小时。**仅「位次渐进」下可用** | 0 |
| 调频记账方式 | 按整词 / 按编码，见下 | 按整词 |

### 默认策略与码表刻意不同

码表侧出厂是「置顶」，英文出厂是「位次渐进」。原因是英文候选**几乎全是前缀匹配**——打 `hel` 出 `hello` / `help` / `helper`。

「一次到顶」「逐次提升」这类「用过一次即整体跳到没用过的那批之前」在这里过于激进：一次误选就把词顶到很显眼的位置，而且这类策略的「用过」不衰减，错了就一直错。「位次渐进」每次只前移一半、久不用会回落，更适合前缀匹配为主的方案。

同理「补全词参与调频」出厂是「全部」：英文候选本来就几乎全是前缀补全，收窄到「仅单词」等于把调频关掉大半。

<Callout type="info" title="英文没有「首选保护」">
码表那组「一简位 / 二简位保护前 N 项」是简码位的首选保护，判据是本次输入的码长。英文没有简码位这回事——一个 `a` 后面跟的是几万个词而不是钦定首选，所以这一组在英文里不存在。
</Callout>

### 调频记账方式

| 取值 | 语义 | 效果 |
| --- | --- | --- |
| 按整词（默认） | 记成 `(hello, hello)` | 打 `hel` 选过 `hello` 后，打 `he` 也受益——跨码位共享 |
| 按编码 | 记成 `(hel, hello)` | 各前缀独立学习，与码表侧同口径 |

这一项按**候选来源**生效——混输方案里混进来的英文候选同样按它记账。

## 候选面：原文与大小写变形 <Since v="0.119" /> [#candidate-face]

| 选项 | 说明 | 出厂 |
| --- | --- | --- |
| 首选为输入原文 | 把**你打的那串字母本身**钉在所有词库候选之前 | 开 |
| 大小写变形候选 | 另补出全小写／首字母大写／全大写三条 | 关 |

### 为什么英文方案需要「首选为输入原文」

英文的特殊之处是**输入即内容**——你打的 `hel` 本身就是可以上屏的文本，这一点码表和拼音都没有。

于是开了[词频调整](#词频调整)之后会出现一个别处不会有的困境：`hello` 被顶到首位是你想要的，但这样一来想上屏 `hel` 本身就只剩回车，而回车在连续输入里很打断节奏。把原文钉在最前就解决了这件事——**词频照常在词库那一段里生效，只是不越过原文**。

关掉它则回到「候选全部来自词库」的形态，适合几乎只打完整单词的人。

<Callout type="warn" title="两项都关且词库没命中时，候选是空的">
这不是故障：此时按空格会直接上屏你打的那串字母。
</Callout>

### 与临时英文那两项的关系

同名的两项在[临时英文](/docs/settings/input/temp-modes#临时英文)下**另有一份**，两边各自独立，改一边不影响另一边。默认值还刻意相反：

| | 英文方案 | 临时英文 |
| --- | --- | --- |
| 首选为输入原文 | 开 | 开 |
| 大小写变形候选 | **关** | **开** |

变形那项的差别是场景决定的：临英是「中文里插一个英文词」，`Hello` 这种首字母大写是刚需，而且只打一两个词，多几条候选不碍事；英文方案是长时输入，每条变形都吃掉一个候选位，一整屏候选里有三分之二是同一个词的三种大小写就很浪费。

两边都可以按自己的习惯改。

## 上屏后自动加空格

开启后上屏一个英文词会自动补一个空格，连续打词不必手动按。补与不补的边界：

| 场景 | 补空格 |
| --- | --- |
| 空格、数字键、次/三选键、鼠标点选中候选 | ✅ 都补 |
| 空格上屏原码（打了词库里没有的自造词、缩写） | ✅ 补，与选中候选保持一致 |
| 回车上屏原码 | ❌ 不补——回车是终结性动作，多伴随换行或提交 |
| 标点键顶屏 | ❌ 不补——打 `hello` 直接按 `,` 得到 `hello,`，不会被空格断开 |

这一项按**当前方案**生效：只在英文方案下补空格，中文输入中途插个英文词不会平白多出空格。

## 英文方案的用户词库 <Since v="0.114" /> [#english-user-dict]

英文方案有自己的用户词库，收专有名词、缩写、项目内部词汇这些词库里不会有的词。**编码就是单词本身的小写**——英文词库以小写码做大小写不敏感的前缀匹配，加 `WindInput` 后打 `wind` 就能出。

三种词加不进去，加词会提示无法计算编码：

- **带空格的**（如 `thank you`）—— 带空格的编码会让前缀查询永远命中不到
- **非 ASCII 的**（如 `café`）—— 英文词库的编码空间就是 ASCII
- **一个字母都没有的**（如 `123`）—— 纯数字或纯符号不是英文词

英文**没有临时词库**：临时词库是自动造词的暂存区，而英文没有造词流程。因此它在[词库页](/docs/settings/dict)只有「用户词库 / 词频 / 候选调整」三个子标签。
