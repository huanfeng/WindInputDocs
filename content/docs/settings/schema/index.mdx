设置工具的「方案」页分三张卡片，自上而下是：**输入方案**（管有哪些方案、用哪个）、**全局方案配置**（管四种引擎的默认行为）、**主方案设置**（管反查与临时拼音用谁）。

<Callout type="info" title="先理解一条：行为是全局的，方案文件只存固定参数">
上屏策略、调频、造词、模糊音这些**行为开关是全局配置**，同类方案共享——改一次，所有码表方案（或所有拼音方案）一起变。方案文件只定义引擎的**固定参数**（引擎类型、码长、词库列表、双拼布局）。

想让某个方案与全局不同，用「方案设置 → 码表配置」单独覆盖。详见[核心概念](/docs/start/concepts#config-split)。
</Callout>

## 输入方案

列表展示**全部已安装方案**，每行显示名称与引擎类型徽章（码表 / 拼音 / 混输 / 英文）。已启用的排在前、未启用的排在后，特殊方案独立成区。

### 列表显示

列表上方的「列表显示」下拉里有两个开关：

| 开关 | 作用 |
| --- | --- |
| 隐藏未启用 | 只看已启用的方案 |
| 显示特殊方案 | 让自制的快符表这类[特殊方案](#special-schemas)出现在列表里；已启用的恒显示，不受此开关影响 |

内置的五个方案——全拼、双拼、五笔 86、五笔拼音、**英文**——都是普通方案，两个开关都不勾也看得到。

### 工具栏操作

以下按钮作用于**当前选中的方案**：

| 操作 | 说明 |
| --- | --- |
| ↑ / ↓ | 调整已启用方案的顺序。`Ctrl + Shift + E` 就按这个顺序循环 |
| 设为当前 | 立刻切到该方案（同时持久化） |
| 设置 | 打开[方案设置对话框](#方案设置对话框) |
| 删除 | 删除用户方案（内置方案不可删除），同时清理其词库数据与未被共享的资源文件 |
| 刷新 | 重新加载方案列表 |
| 导入 / 导出 | [方案包](#import-export)的导入导出 |

也可以直接编辑 `%APPDATA%\WindInput\config.toml`：

```toml
[schema]
active = "wubi86"                              # 当前使用的方案
available = ["wubi86", "wubi86_pinyin"]        # 已启用列表，顺序即循环顺序
```

### 方案设置对话框

选中方案后点「设置」打开。**里面有哪些内容随方案的引擎类型变化**——这是最容易困惑的地方，对照下表即可。

对话框分两个标签页，按**你想做什么**分组，而不是按配置落在哪个文件：

| 标签页 | 内容 | 哪些方案有 |
| --- | --- | --- |
| 基本配置 | 名称、类型、来源、版本、作者、描述（只读）；[切换到本方案按键](#schema-hotkey)、[引导键](#special-schemas)、[方案级按键自定义与总览](#schema-keys)；逐个开关方案随附的[扩展词库](#扩展词库) | 全部（词库部分限有词库的方案） |
| 方案自定义 | [本方案行为](#schema-behavior)；[双拼布局](/docs/settings/schema/pinyin#双拼布局)、[辅助码](/docs/settings/schema/pinyin#aux-code)、[方案级码表配置](#schema-codetable)、特殊模式呈现 | 本方案行为全部方案都有，其余按方案类型 |

「方案自定义」从 0.119 起**任何方案都至少有[本方案行为](#schema-behavior)一节**；其下的双拼布局、码表配置等仍按引擎类型出现，拼音、混输这类方案在那部分是空的（内核只对码表类给出可覆盖的引擎参数）。

引擎类型为**混输**的方案只有「基本配置」有内容——它自己不拥有词库，也没有独立的行为参数。

<Callout type="info" title="对话框没有独立的保存按钮">
里面的改动关闭对话框后**由底栏的「应用设置 / 保存并退出」统一提交**，与其它页面一致。它们背后写两个地方（热键进 `config.toml`，码表配置与词库开关进 `schema_overrides\<方案ID>.toml`），但你不需要关心分别。「重新加载」会连同这些未提交的改动一并丢弃。
</Callout>

### 切换到本方案按键 <Since v="0.114" /> [#schema-hotkey]

`Ctrl + Shift + E` 是循环切换，方案多了要按好几次。可以给单个方案绑一个直达热键，按下直接切过去：**选中方案 → 设置 → 按键设置 → 切换到本方案按键**。

两种模式下都生效——切到英文方案之后还得能按键切回来，所以它不像其它快捷键那样限定中文模式。落点是全局 [`keys.key_actions`](/docs/guides/config/keys#schema-hotkeys) 里的 `switch_schema:<方案id>`（旧的 `keys.schema_hotkeys` 已废弃，不再生效也不自动迁移）。

**不必先启用**：直达热键可以切到没加入 `available` 的方案。英文方案的典型用法就是这样——不占循环切换的位置，用热键切过去打一段，再切回来。首次切过去时会现加载词库，可能有短暂停顿，之后就缓存住了。

### 特殊方案与引导键 <Since v="0.114" /> [#special-schemas]

**特殊方案**指方案文件里标了 `[schema].hidden = true` 的方案。它们默认不出现在方案列表里——勾选「**显示特殊方案**」即可看到并启用；已启用的恒显示，不受该开关影响。

<Callout type="info" title="内置方案里没有特殊方案">
全拼、双拼、五笔 86、五笔拼音、**英文**这五个内置方案都是普通方案，正常出现在列表里，不需要勾「显示特殊方案」。

这个开关是给**自制的小码表**准备的：快符表、生僻字表、术语缩写表这类「插一个符号就走」的方案，混在主方案列表里是噪音，所以作者会给它们标上 `hidden`。
</Callout>

方案文件里声明了 `[overlay]` 段的方案还可以配**引导键**：**选中方案 → 设置 → 按键设置 → 引导键**。与切换到本方案按键不同，引导键是在中文输入中途按下即**临时进入**，打完一段自动退回原方案。同一个对话框里还多出一节「**特殊模式**」，可调进入即展示候选与候选排列。

这一节**只在方案声明了 `[overlay]` 时出现**——「是不是特殊方案」是方案的固有属性，由方案文件决定，不是随手勾选的开关。所以第一次要手写方案文件，写法见[引导键特殊模式](/docs/guides/special-modes)。

<Callout type="info" title="hidden 与 overlay 是两回事">
`hidden` 管「列不列进方案列表」，`[overlay]` 管「能不能被引导键临时进入」。上面五个内置方案两个都没有，所以它们没有引导键那一行。自制的快符表通常两个都写。
</Callout>

特殊方案本质就是**码表方案**，只是靠引导键进入。所以它同样有用户词库、词频、候选调整，也同样能单独设一套上屏行为——但它**不继承全局码表配置**，没写的字段取内置默认值，见[引导键特殊模式](/docs/guides/special-modes#自动上屏策略)。

### 方案级按键自定义与总览 <Since v="0.118" /> [#schema-keys]

同一节里还有三行，都在 **选中方案 → 设置 → 按键设置** 下：

| 入口 | 管什么 | 落点 |
| --- | --- | --- |
| 本方案-按键自定义 | 给一个键指定**功能**（进模式、切方案、切状态） | 方案文件的 [`[key_actions]`](/docs/guides/config/keys#key-actions) |
| 本方案-输入中按键自定义 | 这个键在**输入中**（有编码或候选）干什么（翻页、选词、放弃） | 方案文件的 [`[session_actions]`](/docs/guides/config/keys#schema-session-actions) |
| 按键总览 | 这个键**现在到底**干什么，以及来自哪一层（本方案 / 全局**两层都列**） | 不写任何配置（只展示） |

前两行的界面与全局那两个入口完全一样——一行一条绑定，点「添加 / 修改」弹出同一个[按键选择对话框](/docs/settings/keys#custom-keys-howto)。

它们是**逐键覆盖**全局那两张表：方案只写想改的键，其余继承全局。要在本方案里**关掉**一个全局绑定，功能选「不启用」写成显式的 `none`——把那一行删掉只是回到继承全局，不是禁用。

<Callout type="info" title="总览为什么不能编辑">
一个键的当前动作可能来自全局表、方案表，也可能来自 `page_keys` 这类键组的折算。总览若能改，就得替你决定写回哪一层——那会变成第二个真相源，两边慢慢对不上。所以它只负责回答「现在是什么、来自哪」，改还是回各自的入口。
</Callout>

### 本方案行为 <Since v="0.119" /> [#schema-behavior]

**选中方案 → 设置 → 方案自定义 → 本方案行为**。声明「切到本方案时」的表现：

| 项 | 取值 | 出厂（内置方案） |
| --- | --- | --- |
| 标点 | 跟随全局 / 中文标点 / 英文标点 | 跟随全局（**英文方案为英文标点**） |
| 候选排列 | 跟随全局 / 竖排 / 横排 | 跟随全局（**英文方案为竖排**） |
| 加载短语 | 开 / 关 | 开（**英文方案为关**） |
| 候选注释 <Since v="0.119" /> | 跟随全局 / 本方案专用模板 / 本方案不显示 | 跟随全局 |
| 自定义标点 <Since v="0.119" /> | 跟随全局 / 本方案专用映射表 | 跟随全局 |

每一项都可以对**任何方案**设置，不是英文专属——英文只是把前三项都用上了的那个例子。典型用法还有「拼音方案横排看着舒服，五笔竖排」这种。

选「跟随全局」的项**完全不受本方案影响**，与这个功能出现之前的行为一模一样。

<Callout type="info" title="「跟随全局」是回到原值，不是保持现状">
五笔（跟随全局）下用中文标点 → 切到英文方案变英文标点 → **切回五笔会变回中文标点**。

要是你在五笔下本来就把标点设成了英文，这一趟往返之后仍然是英文——还原的是**你自己的偏好**。
</Callout>

方案期间**手动改仍然算数**：在英文方案里按中/英标点切换键改成中文标点，本次停留期间一直有效；切走再切回来，重新按方案的声明落地。候选排列同理。

「加载短语」关掉后，本方案不出[短语](/docs/settings/dict/phrases)候选，短语也不再占用码位。英文方案出厂即关——`date`、`tel`、`em` 这类短语码同时也是英文单词，打英文时会莫名跳出中文内容。

按分类只加载一部分短语（`categories` / `exclude_categories`）目前**仅配置文件**，写法见[方案级行为](/docs/guides/schemas#schema-behavior)。

#### 候选注释 <Since v="0.119" /> [#schema-comment-template]

点这一行的「设置」，横排与竖排各有一个「自定义」勾选框加输入框。三种状态：

- **不勾**：跟随[全局的注释模板](/docs/settings/appearance/candidate-comment)
- **勾上填模板**：本方案改用你填的
- **勾上留空**：本方案**不显示注释**——这与「跟随全局」是两回事

横竖两个方向各自独立，只配一个、另一个跟随全局是常见用法。

#### 自定义标点 <Since v="0.119" /> [#schema-punct-mappings]

点这一行的「设置」，勾上「**使用本方案的标点表**」，就能给这个方案单独配一份[标点映射](/docs/settings/input/punctuation#自定义标点映射)。表格与全局那份完全一样：五列、点单元格改字符、留空恢复该格默认。

典型用法是**代码输入方案**：写代码时想让 `.` `,` `;` 一律直出半角，而中文方案照旧出全角标点。以前只能来回切标点态，现在切到那个方案就自动是你要的那套。

<Callout type="warn" title="开启后全局那份整份不再生效">
方案表是**整份替换**，不是「在全局表基础上改几行」。勾上之后，你在[全局自定义标点](/docs/settings/input/punctuation#自定义标点映射)里配的行**全部不参与**——包括全局那个「启用自定义标点」总开关也一并被换掉：**总开关关着，声明了自己表的方案照样出自定义符号**。

所以从跟随切到自定义时，别只改想改的那一行——先确认整张表就是你要的样子。表里没改过的行走的是内置默认转换（`.` → `。` 那些），不是全局表里的值。
</Callout>

不勾就是完全跟随全局，与这个功能出现之前一模一样。落盘同样在 `schema_overrides\<方案ID>.toml`，取消勾选即从该文件里删掉这一段。

<Callout type="info" title="方案作者写了表时，取消勾选回到的是作者那张">
与[方案级码表配置](#schema-codetable)同理：取消勾选只清除**你改的那层**。若方案作者在 `<方案ID>.schema.toml` 里写了 `[punct.custom_mappings]`，取消后回到**他写的那张表**，不是回到全局——重新打开设置页会看到勾选仍然是开着的。要连作者那层一起去掉，只能编辑方案文件。

内置方案都不写这一段，所以这只会出现在你自己装的第三方方案上。
</Callout>

### 方案级码表配置 <Since v="0.114" /> [#schema-codetable]

码表方案默认跟随[全局码表配置](/docs/settings/schema/codetable)——改一次，所有码表方案一起变。想让某个方案的**某几项**单独一套，在 **选中方案 → 设置 → 方案自定义** 里，把那几行左侧的勾选框勾上。

那些项与全局那份逐条相同（顶码上屏、精确匹配、词频调整等），改的只是作用范围。

<Callout type="info" title="每一项各自决定跟不跟随" >
勾选是**逐项**的（0.119 起）：勾上哪一项，就只有那一项脱离基线，其余照旧跟随。不必为了改一个开关让整个方案都不再跟随全局。

- **没勾**：右侧显示的是**跟随值**（取消覆盖后实际会用的那个），只读
- **勾上**：右侧变成可操作的控件，从当前生效值起步

控件左边那一列写明这一项现在跟的是谁：**跟随全局**、**方案自带**（方案作者在方案文件里写了）、或**已自定义**（你改的）。
</Callout>

最典型的用法是给快符表单独开**词频调整**：小符号表的顺序往往是作者精心排过的，全局开了调频未必适合它；反过来想让快符学习使用频率、又不想动五笔的调频，也只能靠这里。

落盘位置是 `schema_overrides\<方案ID>.toml`，不改方案文件本身，方案后续更新不受影响。取消勾选就是把该项从这个文件里删掉。

右上角的**全部恢复跟随**把这个方案的所有覆盖一次清空，包括设置里不显示的隐藏项。

<Callout type="warn" title="「方案自带」的项取消勾选后不会回到全局">
若方案作者在 `<方案ID>.schema.toml` 里显式写了某项，它属于方案定义的一部分。取消勾选只清除你改的那层，该项回到**方案作者写的值**而不是全局值——这也正是那一列会写「方案自带」的原因。要连方案作者那层一起改，只能编辑方案文件。内置方案不写任何这类项，所以「方案自带」只会出现在你自己装的第三方码表上。
</Callout>

### 扩展词库

方案除主词库外，还可随附若干**扩展词库**（表情、符号、地名等）。它们与主词库共同参与候选排序，可按需独立开关，是在不修改方案文件的前提下调整候选范围的最常用入口。

每个条目一个开关，下方小字说明该词库的内容范围（由方案作者预设）。主词库不出现在这个列表里——它始终启用。

五笔方案随附的扩展词库：

| 词库 | 默认 | 说明 |
| --- | --- | --- |
| 极点五笔主词库 | —— | 主词库，始终启用，不在列表中 |
| 扩展词库 | 启用 | 新词、网络用语、生僻词等非常用词条 |
| Emoji 表情 | 启用 | 按五笔编码检索 emoji；输入 `emoj` 可查看常用表情 |
| 行政区域 | 关闭 | 省市县区等地名词条，按需启用 |

<Callout type="info" title="开关只记「开或关」，不冻结词库定义">
覆盖层按词库 id 只接受启用状态一个字段，词库的路径、名称、顺序等始终以方案文件为准。因此方案升级后新增或调整过的词库都能正常透传，不会被你点过的开关冻结在旧版本。若想替换词库文件本身，见[同结构覆盖机制](/docs/guides/config#同结构覆盖机制)。
</Callout>

### 导入与导出方案 [#import-export]

方案以**方案包**（`.zip`）形式分发，便于备份或分享社区码表方案（如 [WindInputCodeTable](https://github.com/huanfeng/WindInputCodeTable) 收集的第三方码表）：

- **导入** —— 选择包文件后先预览包内方案信息，确认后选择**合并**或**替换**导入
- **导出** —— 将选中方案连同其引用的资源文件（词库、双拼布局、拆字库、字根字体）打包导出
- 包带[随包配置](/docs/settings/dict/import-export#config-patch)时 <Since v="0.118" />，确认框会逐项列出将修改的配置项
- 导入不止这一个入口 <Since v="0.118" />：[高级页统一导入](/docs/settings/advanced#import-export)、双击 `.wpkg`、网页[一键安装链接](/docs/guides/import-export#protocol)走的都是同一个确认流程，小方案还能以[纯文本](/docs/guides/import-export#schema-text)分发

<Callout type="info" title="方案包不含个人数据">
方案包只有方案配置与引用资源，**不含**你的用户词、词频、候选调整。把方案分享给别人不会连带泄露个人输入记录；换机时要带走个人数据请用[整机备份](/docs/settings/advanced#备份与还原)。
</Callout>

包内布局、`package.toml` 字段与资源收集规则见[导入与导出格式](/docs/settings/dict/import-export#方案包zip)。要从零创建方案，见[方案配置](/docs/guides/schemas)。

## 主方案设置 [#main-schema]

这两项决定「当需要用到码表 / 拼音、但当前方案不是它」时，去找哪一个方案。

| 选项 | 说明 |
| --- | --- |
| 主码表方案 | 主力码表方案（如五笔 86）。**拼音方案的编码反查与编码提示基于此方案的码表**——拼音候选旁显示的五笔编码就是从这里查的 |
| 主拼音方案 | [临时拼音](/docs/settings/input/temp-modes#临时拼音)、[快捷输入](/docs/settings/input/quick-input)的拼音子模式使用的拼音方案（可选双拼）。留空 = 全拼 |

<Callout type="warn" title="混输方案的拼音不受「主拼音方案」影响">
混输方案的拼音来自它自己方案文件里 `[engine.mixed]` 的 `secondary_schema` 字段，与这一项无关。改混输用哪个拼音要改方案文件，见[混输方案配置](/docs/settings/schema/mixed#no-own-dict)。
</Callout>

确切配置键与取值见[方案与引擎配置](/docs/guides/config/schema#方案选择)。
