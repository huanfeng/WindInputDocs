清风输入法在中文输入的间隙提供几种「临时模式」：码表忘码时临时用拼音、临时切一段英文、输入网址。它们都用完即退，自动回到原方案。

「输入」页里对应三张卡片。对应配置段是 `config.toml` 的 `input.temp_pinyin` / `input.temp_english` / `input.url`，完整键名见[输入行为配置](/docs/guides/config/input)。

## 临时拼音

码表方案（如五笔）下忘码时，按触发键临时切换为拼音输入，选词上屏后回到码表。

| 选项 | 说明 | 出厂 |
| --- | --- | --- |
| 临时拼音触发键 | 可多选，只收符号键 | 反引号 `` ` `` |
| 候选窗布局 | 跟随全局 / 强制竖排 / 强制横排 | 跟随全局 |

可选触发键：`` ` ``、`;`、`'`、`,`、`.`、`/`、`\`、`[`、`]`。

<Callout type="info" title="想用字母键触发？去方案页配">
`z` 这类死码字母不在这个列表里——它在[码表方案配置 → z 键引导功能](/docs/settings/schema/codetable#z-key-action)里配。启用后 `z` 开头的编码将无法输入，这是代价。
</Callout>

临时拼音用哪个拼音方案，由[主拼音方案](/docs/settings/schema#main-schema)决定（可选双拼）。拼音消歧的分隔符在[拼音方案配置](/docs/settings/schema/pinyin#拼音分隔符)里设。

也支持配**专用直达热键**：按热键直接进入，无需先在码表中忘码。

### 候选与主路径对齐 <Since v="0.114" /> [#temp-pinyin-parity]

0.113 及以前临时拼音有两处与主拼音路径不一致，0.114 已对齐：

- **深处的字翻页翻不到** —— 临拼固定只向引擎取 50 条，又没有翻页扩容通路，于是 `ying` 打不出「瑩」（该字排在第 158 位），翻多少页都没有。现改为一次取全量，翻页对已取回的候选切片，能翻到底
- **「检索范围」设置对临拼无效** —— 临拼此前完全不经过候选过滤，出厂的「智能」档下比主路径多出数百个生僻字（`ying` 实测 299 条 vs 主路径 76 条）。现已按主路径同序接入，[候选检索范围](/docs/settings/input#候选检索范围)设成什么，临拼就跟着什么

### 与拼音方案共用同一份用户数据 <Since v="0.121" /> [#temp-pinyin-user-data]

临时拼音操作的本来就是拼音那一份数据，0.121 起读写两端都对齐了：

- **候选调整**（置顶 / 隐藏）与拼音方案**共享同一份规则**。在全拼下把某个词置顶，切回五笔用引导键进临拼打同样的音，置顶照样生效
- **词频**也落进同一个桶。开关跟着[拼音方案的调频开关](/docs/settings/schema/pinyin#词频调整)走，不再取码表那一档；临拼学到的词，在全拼、双拼下同样排得靠前
- 临拼指向双拼时，规则按**全拼归一码**记账（打 `hc` 与打 `hao` 认的是同一条规则）

<Callout type="warn" title="旧数据不迁移">
0.121 之前临拼的词频错落在主码表方案（如 `wubi86`）名下。那些拼音码本就是错放的，不会迁移过来——只有手动开过码表调频的用户才会有这批数据。
</Callout>

## 临时英文

中文模式下，按 `Shift + 字母` **始终**可进入临时英文模式，无需单独的「启用」开关。也可配置符号触发键，以全小写字母进入。

- 调频与上屏补空格跟随[英文方案配置](/docs/settings/schema/english) <Since v="0.118" />，与英文方案共用一份学习数据；右键菜单里的置顶 / 隐藏候选同样生效。首候选恒是所打原文，不参与重排

进入与退出：

1. 按 `Shift + 字母` 触发（或配置的触发键）
2. 继续输入英文内容
3. 按 `Space` 或 `Enter` 上屏后自动恢复中文模式

| 选项 | 说明 |
| --- | --- |
| 临时英文触发键 | 可多选，也可留空（仍可用 `Shift + 字母` 进入） |
| Shift+字母行为 | 进入临时英文模式 / 直接上屏大写字母 |
| 显示英文候选 | 查询英文词库显示候选词 |
| 首选为输入原文 <Since v="0.119" /> | 把你打的那串字母本身钉在词库候选之前，见下 |
| 生成大小写变形候选 | 补出全小写、首字母大写、全大写三种形态，见下 |
| 候选跟随输入的大小写 <Since v="0.121" /> | 词库候选随你打的大小写走，见下 |
| 切换候选大小写的键 <Since v="0.121" /> | 打英文时按它在三档大小写之间循环，见下 |
| 允许输入符号与数字 | 符号与数字直接进缓冲，而非上屏退出或选词 |
| 可输入的字符集 | 上一项放行哪些字符，见下 |
| 空格作为输入字符 | 空格不再上屏，可连续输入多个单词，回车上屏 |
| 候选窗布局 | 跟随全局 / 强制竖排 / 强制横排，出厂跟随全局 |
| 切换模式时取消大写锁定 | 切换中英文模式时自动取消 CapsLock 状态 |

可选触发键：`` ` ``、`;`、`'`、`,`、`.`、`/`、`\`、`[`、`]`。

<Callout type="info" title="英文候选一行放得下">
全局设成竖排时，把临时英文的候选窗布局设成「强制横排」更省屏幕——这正是三档设计（而非开关）的用处。
</Callout>

### 大小写变形候选

因为 `Shift + 字母` 是进入方式，缓冲的首字母必然是大写，但你想打的未必是首字母大写。所以候选里会补出三种形态供你选：

```text
Hel        ← 你打的原文，排在词库候选之前
hel        ← 全小写
HEL        ← 全大写
help       ← 以下是英文词库匹配，保持词库自身的大小写
helper
Helen
```

这三条变形各占一个候选位——每页 5 条时会吃掉一半，把词库候选挤到下一页。如果你主要用临英做单词补全、不需要大小写变换，可以关掉「生成大小写变形候选」<Since v="0.114" />，候选里就只剩原文和词库匹配。

- 原文那一条也能单独关 <Since v="0.119" />——「首选为输入原文」。两项都关且词库没命中时候选会是空的，这不是故障：此时按空格直接上屏你打的那串字母
- 这两项在[英文方案](/docs/settings/schema/english#candidate-face)下**各有一份、互不影响** <Since v="0.119" />，默认值还刻意相反——变形候选在临英默认**开**（`Shift` 进入决定了首字母必然大写），在英文方案默认**关**（长时输入，每条变形都吃候选位）。改一边不会动到另一边

### 候选跟随输入的大小写 <Since v="0.121" /> [#case-follow-input]

打 `Hi` 出 `Hill`、打 `WoW` 出 `WoWed`——词库候选按你实际按下的大小写逐位改写，出厂开。

**只跟大写**：你打的小写位保持词库原文，所以 `China`、`iPhone`、`Hi-Fi` 这类词自带的大写不会被压平。候选与输入逐位对不上的（短语、命令类候选）整条保持原样，不会出现既不是词库形态、也不是你所打形态的杂合体。

⚠️ 临英由 `Shift + 字母` 进入，缓冲首字母恒是大写，于是开着它临英的词库候选恒为首字母大写形态。想要小写形态，可以用下面的档位键切一下，或者干脆关掉这一项——关掉后词库候选回到词库原文，大小写仍可从变形候选里取。

英文方案下[另有一份](/docs/settings/schema/english#case-follow-input)，两边独立，默认都是开。

### 切换候选大小写的键 <Since v="0.121" /> [#case-cycle-key]

打英文期间（临时英文或英文方案）按这个键，候选在三档之间循环，本次上屏后自动复位：

| 档位 | 打 `Hi` 时的词库候选 |
| --- | --- |
| 跟随输入（默认档） | `Hill` |
| 全大写 | `HILL` |
| 全小写 | `hill` |

出厂**不绑任何键**——不选键就是关闭，没有另一个启用开关。下拉里给了两个：

| 取值 | 说明 |
| --- | --- |
| Caps Lock | Windows 推荐。**macOS 无效**：那边系统只把锁定状态传给输入法，不传这个按键本身 |
| Tab | 两个平台都通，macOS 上用它 |

⚠️ 被选中的键在**打英文期间**用不出原本的功能（Caps Lock 的大写锁定，Tab 的辅助码 / 配对跳出 / 会话动作），其余时候一律照旧。真撞上了启动会告警，但只报「被占用」不说被谁占，得挨个试。

配置键是 `input.english_case_cycle_key`，值域比下拉多三个（`enter` / `space` / `escape`）。它们在输入态都另有语义（Esc 取消组合、回车与空格上屏），所以没放进界面，手写进 `config.toml` 仍然生效。

### 字符白名单 [#temp-english-symbol-chars]

打开「允许输入符号与数字」后，具体放行哪些字符由「可输入的字符集」精确决定 <Since v="0.115" />，出厂值是 `0123456789+-_.@#/`。字符集**逐字符填写**，一个字符就是一个字符，不支持 `a-z` 这类范围写法。留空则一个都不放行。

临英下每个符号键身上原本都压着别的职责，白名单的作用就是把你选中的那些**单独摘出来**改成输入：

| 键 | 未列入白名单（保持原职责） | 已列入白名单 |
| --- | --- | --- |
| `,` `.` `/` 等标点 | 上屏当前候选 + 该标点，退出临英 | 进入缓冲，如 `obj.prop` |
| `;` / `'` | 选第 2 / 第 3 候选 | 进入缓冲 |
| `-` `=`、`[` `]`、`,` `.` | 翻页 | 进入缓冲，如 `e-mail` |
| 数字键 `1`–`9` | 按页选词 | 进入缓冲，如 `mp3`、`x64` |

判定按**字符**而非按键，因此 `+`（Shift + `=`）和 `=` 是两个独立字符：只列 `+` 时，`=` 仍然翻页。

<Callout type="warn" title="出厂值含 . 与 - 的代价">
这两个字符属于成对的翻页键组。出厂把它们放进白名单是为了 `obj.prop` / `e-mail` / `snake_case` 打得出，代价是临英下「上一页」只剩方向键 `↑` 与 `PgUp`，且「打完英文顺手按句号上屏」这条通路失效。不需要代码场景的话，把 `.` 和 `-` 从字符集里删掉即可拿回。
</Callout>

另有一条不受白名单管的规则：**缓冲里一旦出现非字母字符**（例如已经打出 `C++`），数字键一律直接进入缓冲。此时词库查不到东西，候选只剩原文和大小写变形，再把数字当选词键就打不出 `C++11` 了。

## 网址输入

打出完整前缀（如 `http`、`www.`）即进入网址输入模式，可自由输入网址，空格或回车上屏。

| 选项 | 说明 |
| --- | --- |
| 启用网址输入模式 | 开关 |
| 触发前缀 | 识别为网址的前缀（如 `www.` `http` `https` `ftp.`），在对话框中按空格分隔编辑 |

网址输入模式目前不产出候选，候选窗不出现，所以它的「候选窗布局」项在界面上隐藏了（配置键仍在）。

## 候选窗布局的三档语义 [#layout-modes]

临时拼音、临时英文、快捷输入都各有一个「候选窗布局」下拉，控制**进入该模式期间**候选窗的排列方向，退出后自动恢复：

| 选项 | 含义 |
| --- | --- |
| 跟随全局 | 用[外观设置](/docs/settings/appearance#candidate-window)里的候选窗排列——你改全局，本模式跟着改 |
| 强制竖排 | 本模式期间恒定竖排，与全局设成什么无关 |
| 强制横排 | 本模式期间恒定横排 |

它不是一个「开 / 关」的开关：**「跟随全局」和「强制竖排」的区别只在全局本身就是竖排时才看得出来**——前者会跟着你以后对全局的改动走，后者不会。也正因为有三档，才能表达「全局竖排、但临时英文横排」这种组合。

各模式的出厂默认：快捷输入是**强制竖排**，临时英文与临时拼音都是**跟随全局**。

<Callout type="info" title="配置文件里的对应项">
这三项对应配置里的 `candidate_layout`（取值 `follow` / `vertical` / `horizontal`）。引导键特殊模式与快捷加词面板也有同名项，只是没有图形界面，详见[模式级候选布局](/docs/guides/config/input#模式级候选布局)。
</Callout>

## 引导键特殊模式

在码表方案下，按一个「引导键」可临时进入另一套独立的小型码表（快符、生僻字、术语缩写等），完成后自动退回原方案。

引导键本身可以在**方案页 → 选中方案 → 设置 → 按键设置 → 引导键**里配；条目的其余字段（进入即展示候选、候选窗布局、注释模板等）目前仍需手写 `config.toml`。配置方法、退出条件与候选行为详见[引导键特殊模式](/docs/guides/special-modes)。

## Ctrl / Alt 组合键不会被吞 <Since v="0.114" /> [#ctrl-alt-guard]

在临时英文、临时拼音、快捷输入、网址输入、引导键特殊模式这五种模式里，带 Ctrl / Alt 的按键按主输入路径的语义处理：

- **缓冲区非空** —— 放弃整段待输入内容并隐藏候选窗，该按键交还宿主
- **缓冲区为空** —— 直接透传给宿主

0.113 及以前，`Ctrl + E` 这类组合键会被当成字面 `e` 插进缓冲区，宿主程序收不到该快捷键。

<Callout type="info" title="想让某个组合键在候选窗显示期间生效">
把它配成候选窗快捷键（置顶、删除候选等）即可——那一层在上述守卫**之前**分派，天然优先，且五种模式一次接通。见[按键设置](/docs/settings/keys#word-manage)。
</Callout>
