## 候选检索范围

「字符与标点」卡片的第一项，控制**生僻字要不要出现在候选里**。三档：

| 取值 | 范围 |
| --- | --- |
| 智能（默认） | 按通用规范汉字表过滤，但保留一部分常见但不在表内的字 |
| 常用字 | 只出通用规范汉字表里的字，候选最干净 |
| 全部字符 | 不过滤，GB18030 全集，生僻字全出 |

也可以随时从[功能主菜单](/docs/start/first-input#context-menu)的「检索范围」子菜单切换，不必打开设置。

### 翻到底临时放宽 [#scope-relax]

「智能」档下点右侧的**扩展设置**，里面有两项：

| 选项 | 说明 |
| --- | --- |
| 翻到底临时放宽范围 | 候选翻到最后一页后**再按一次**向后翻页键，本次输入临时显示全部字符，上屏后自动恢复 |
| 放宽候选标记 | 给临时多出来的那些候选加个前缀，与正常候选区分；留空则不加 |

这是为「打一个被同码常用字挡住的生僻字」准备的：不必去设置里切档位、打完再切回来，多按一次翻页键即可。仅「智能」档生效。

<Callout type="info" title="临时拼音也跟着这个设置走">
0.114 起临时拼音已按主输入路径同序接入候选过滤——这里设成什么，临拼就跟着什么。此前临拼完全不过滤，在「智能」档下比主路径多出数百个生僻字。
</Callout>

## 按键行为

四项，都是下拉：

| 选项 | 说明 |
| --- | --- |
| 回车键功能 | 有编码时按回车怎么处理 |
| 空码时空格键功能 | 无候选时按空格怎么处理 |
| 空码时标点键功能 <Since v="0.118" /> | 无候选时按标点/符号键怎么处理编码 |
| 数字小键盘功能 | 小键盘数字键的行为 |

前三项共用同一组取值：

| 取值 | 行为 |
| --- | --- |
| 上屏编码 | 把你打的原始编码字母上屏，清空缓冲 |
| 清空编码 | 直接丢弃缓冲，什么都不上屏 |

「空码」就是打了码却一个候选都没出来，多半是打错了字根。这三项管的都是这时候那串废码的去向。标点那项无论选哪个，**标点本身照常上屏**——只是编码要不要跟着一起出去。

<Callout type="info" title="0.118 之前这两项列了四个取值">
「上屏并继续输入」「忽略」从未被实现过，选了它们的实际效果就是「上屏编码」。0.118 起下拉只保留真实存在的两项，已经设成那两个值的配置会在加载时自动归一为「上屏编码」——行为和之前完全一样，不需要重新设置。
</Callout>

数字小键盘：

| 取值 | 行为 |
| --- | --- |
| 直接输入数字 | 小键盘就是打数字，不参与选词 |
| 同主键盘区数字 | 小键盘与主键盘数字键等价，可用于候选选择和快捷输入 |

## 候选无效按键

这三项回答同一个问题：**你按了一个选词键，但那个位置根本没有候选，该怎么办？**

| 选项 | 触发场景 |
| --- | --- |
| 数字键无效时 | 按的数字超出当前页候选数量（如只有 3 个候选却按了 `7`） |
| 次选三选键无效时 | 候选不足 2 / 3 个却按了次选或三选键 |
| 以词定字键无效时 | 候选词长度不足却按了以词定字键 |

三项共用同一组取值：

| 取值 | 行为 |
| --- | --- |
| 不起作用（默认） | 忽略这次按键，编码与候选都不变 |
| 上屏编码 | 上屏当前的原始编码 |
| 上屏并继续输入 | 上屏编码后保持输入状态 |

<Callout type="info" title="这一组在配置文件里属于 keys 域">
虽然显示在「输入」页，配置键是 `keys.overflow.*`。见[按键配置 · 无效按键策略](/docs/guides/config/keys#无效按键策略keysoverflow)。
</Callout>

## 简入繁出

打简体、出繁体，基于 OpenCC 词典转换。

| 选项 | 说明 |
| --- | --- |
| 启用简入繁出 | 总开关。候选与上屏均输出繁体 |
| 转换变体 | 目标字形与词汇风格，见下 |

| 变体 | 说明 |
| --- | --- |
| 标准繁体 | 通用繁体字形 |
| 台湾繁体 | 台湾标准字形 |
| 台湾繁体（含词汇） | 台湾字形 + 词汇替换（如「软件」→「軟體」） |
| 香港繁体 | 香港标准字形 |

日常开关用快捷键 `Ctrl + Shift + J`，或[功能主菜单](/docs/start/first-input#context-menu)里的「简入繁出」。变体只能在这里选。

## 默认状态

管的是**每次激活输入法时从什么状态开始**。

| 选项 | 说明 | 出厂 |
| --- | --- | --- |
| 中英状态作用域 | 全局统一 / 按应用独立 | 全局统一 |
| 记忆前次状态 | 恢复上次的中英文、全半角和标点状态 | 关 |
| 初始语言模式 | 中文 / 英文 | 中文 |
| 初始字符宽度 | 半角 / 全角 | 半角 |
| 初始标点模式 | 中文标点 / 英文标点 | 中文标点 |

**开启「记忆前次状态」后，下面三个初始项会置灰**——记忆和固定初始值是互斥的两条路。

### 中英状态作用域

| 取值 | 语义 |
| --- | --- |
| 全局统一 | 所有应用共享同一个中英状态。在 A 里切到英文，切到 B 也是英文 |
| 按应用独立 | 每个应用各自记忆中英文。适合「游戏里要保持英文、聊天窗要中文」这类场景 |

按应用独立的记忆**不持久化**，重启输入法后重置。

<Callout type="info" title="与右键菜单「应用独立配置」的关系">
这一项管的是「每个应用各自记住上次状态」；[功能主菜单](/docs/settings/menu#app-config)的「初始输入模式」管的是「切进这个应用时**强制**切到某个状态」。两者可以叠加：先按规则套用初始值，之后在该应用内的手动切换再被独立记忆。
</Callout>

## 按键冲突提示

「输入」页顶部可能出现一条**琥珀色警告条**，列出当前的按键冲突（如快捷输入触发键与次选键撞了、临时拼音触发键与临时英文触发键撞了）。它固定在内容区顶部、不随页面滚动，切页也常驻，直到冲突解决为止。

同一个物理键只能分配给一项功能。冲突的完整判定规则见[按键设置 · 冲突与优先级](/docs/settings/keys#冲突与优先级)。
