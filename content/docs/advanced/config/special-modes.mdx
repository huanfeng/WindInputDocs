---
title: 引导键特殊模式
description: 用引导键临时进入自建小码表（快符、生僻字等）的配置方法、退出条件与候选行为
---

在码表方案下，按一个「引导键」临时进入另一套独立的小型码表，完成后自动退出回到原方案。常见用途：快速符号（俗称「快符」）、生僻字、专业术语缩写等。它属于 `[schema]` 域的 `[[schema.special_modes]]`，**没有图形界面，需手工写配置**。

<Callout type="warn" title="特殊模式默认为空，需要你自己配置">
`schema.special_modes` 出厂是**空列表**，安装后没有任何可用的特殊模式——包括「快符」。它不是一个开箱即用的功能，而是一套让你自建小码表的机制。

启用需要你准备**两样东西**：`config.toml` 里的 `[[schema.special_modes]]` 配置块，以及它引用的方案文件与词库。唯一预置的引导键模式是 `;` 触发的「快捷」混输模式，见[快捷输入](/docs/input/quick-input)。
</Callout>

工作原理：

1. 按下配置的**引导键**（如 `\`）进入对应特殊模式：编码为空时直接进入；已有候选时先上屏当前高亮候选，再进入模式
2. 候选窗口显示**模式徽标**（如「快符」），此时输入的字符在该模式的码表中检索
3. 上屏一个候选后自动退出，回到原方案；也可按 `Esc` 手动退出

若引导键引用的方案加载失败，该键**不会被拦截**，会按普通标点处理——这是判断配置是否生效的快捷方法：按下引导键却打出了标点，说明方案没加载上。

<Callout type="info" title="和快捷输入的区别">
快捷输入（`;` 触发）内置了数字转换、计算器、日期等功能，使用内置逻辑处理；特殊模式则是完全自定义的码表，适合放置任意词条，更灵活。
</Callout>

## 配置

特殊模式通过全局配置文件 `config.toml` 的 `[[schema.special_modes]]` 数组配置，可定义多组。每个特殊模式条目只描述「用哪个引导键、显示什么名字、触发哪个方案」，真正的码表和全码上屏策略都定义在被引用的方案文件 `<方案id>.schema.toml` 里。

```toml
[[schema.special_modes]]
id = "quick_symbols"             # 模式唯一 ID（必填）
name = "快符"                    # 候选窗口显示的模式名（必填）
short_name = "符"                # 模式指示短称（可选；留空取 name 首字）
trigger_keys = ["backslash"]     # 引导键列表（必填，至少一个）
schema = "quick_symbols"         # 引用的方案 id（必填）
hotkey = ""                      # 专用直达热键（可选，如 "ctrl+shift+u"；空=不注册）
show_all_on_enter = false        # 进入模式即展示候选（可选，默认 false，见下文）
```

引导键取键名，支持常用符号键，也支持单个字母 `a`–`z`：

| 键名 | 按键 |
| --- | --- |
| `backslash` | `\` |
| `backtick` / `grave` | `` ` `` |
| `semicolon` | `;` |
| `quote` | `'` |
| `comma` | `,` |
| `period` | `.` |
| `slash` | `/` |
| `lbracket` | `[` |
| `rbracket` | `]` |
| `minus` | `-` |
| `equal` | `=` |

<Callout type="warn" title="按键冲突">
若引导键已被次选键、临时拼音等功能占用，设置工具会提示冲突。同一个键只能分配给一项功能。

多个特殊模式按配置顺序匹配，**首个命中者生效**——两个模式配了同一个引导键时，后面那个永远进不去。
</Callout>

## 退出方式

特殊模式的退出条件比"选中候选"要多，完整清单：

| 操作 | 行为 |
| --- | --- |
| 选中候选（空格 / 数字键 / 次选键） | 上屏并退出 |
| `Esc` | 丢弃输入，退出 |
| 退格 / 删除把编码删空 | 退出（编码已空时按退格也退出） |
| 空格且当前无候选 | 退出 |
| `Enter` 且编码非空 | 上屏编码原文 |
| `Enter` 且编码为空 | 上屏引导符本身并退出（回车行为设为「清空」时则只退出） |
| 再按一次引导键（编码为空时） | 输出该标点并退出 |
| 输入其他标点 | 上屏当前高亮候选 + 转换后的标点，退出 |
| 切换焦点 / 切换模式 | 自动退出 |

此外，被引用方案的全码策略触发时会自动上屏并退出，见下文[自动上屏策略](#自动上屏策略)。

## 直达热键

除引导键外，每个特殊模式还可配置一个**专用直达热键**（`hotkey`，形如 `"ctrl+shift+u"`），与引导键共存：按热键直接进入该模式，且组合区**不写入引导符**（引导键进入时首位是引导符，热键进入则从空编码开始）。仅中文模式下生效。

## 自动上屏策略

特殊模式输入时是否自动上屏，由**被引用方案**的 `[engine.codetable]` 全码策略决定，与该方案作为普通方案使用时一致：

- **全码唯一自动上屏**：候选唯一且无更长前缀时自动上屏，适合符号、常用词
- **固定码长自动上屏**：达到指定码长且候选唯一时自动上屏，适合定长码表
- **手动选择**：始终按数字 / 空格选择，适合需要精确控制时

被引用的方案不会出现在正常的方案切换列表中，只在按下引导键时懒加载触发。方案文件与码表词库的写法见[输入方案管理](/docs/customize/schemas)。

## 精确匹配与空码补全

特殊模式的候选检索是否走**精确匹配**、以及空码时是否**补全后续编码**，同样由被引用方案的 `[engine.codetable]` 决定，规则与该方案作普通方案时完全一致（见[码表引擎配置](/docs/advanced/config/schema#码表引擎schemacodetable)）：

- `single_code_input`：精确匹配模式，关闭前缀枚举，只显示编码完全匹配的候选
- `single_code_complete`：精确匹配下当前编码无精确候选、但更长前缀有候选时，补一条「首位后续码」。**任意未满码长**都会补（不限某个具体码长），只有打满全码仍无候选时才不补

<Callout type="warn" title="设置工具里的「精准匹配」不会流到特殊模式">
在设置工具中对**当前码表方案**（如五笔）开启的「精准匹配」，只写入那个方案的覆盖层，**不会自动应用到特殊模式引用的方案**。特殊模式方案若自己没配，会回落到全局基线 `schema.codetable`（其中 `single_code_input` 默认为 `false`），因而表现为「主方案精确匹配、特殊模式却不精确」。

要让某个特殊模式也精确匹配，需在**它引用的方案**上单独开启：改方案文件 `<方案id>.schema.toml` 的 `[engine.codetable]` 段，或用户覆盖层 `schema_overrides/<方案id>.toml` 的 `[codetable]` 段（后者等同设置工具对该方案的写入）。
</Callout>

例如在被引用方案的 `[engine.codetable]` 段开启精确匹配：

```toml
[engine.codetable]
single_code_input = true
# single_code_complete 全局默认为 true，会自动继承；也可显式写死
```

## 进入即展示候选

默认情况下，进入特殊模式后候选窗为空，敲入编码才出候选。把该模式的 `show_all_on_enter` 设为 `true`，则**一进入就展示被引用方案码表的候选**，可直接翻页浏览——适合快符、生僻字分类符号这类**小码表**。

展示数量**遵循该方案的 `single_code_input`**：

- **非精确匹配模式**：展示码表首页候选，按[每页候选数](/docs/advanced/config/ui)分页浏览
- **精确匹配模式**：最多展示 1 条（与 `single_code_complete`「取首位后续码」同语义）

<Callout type="info" title="仅宜小码表">
`show_all_on_enter` 面向小符号表。若引用的是大码表（成千上万条），进入时会遍历整表取首页，有一定开销，不建议开启。
</Callout>

## 候选行为

特殊模式的候选与主方案完全隔离，且有两点与常规输入不同：

- **不做二次排序** —— 候选保持被引用方案的引擎输出顺序。想调整顺序请用该方案自己的 [`base_sort` / `base_order` / `default_weight`](/docs/customize/schemas#排序配置四件套)
- **不做简繁变体展开** —— 即使开启了简繁转换，特殊模式的候选也不会展开繁体变体（临时拼音与快捷输入模式则会）

引导符只作显示，**不参与检索**：按 `\` 后输入 `bd`，查询的是 `bd` 而不是 `\bd`。

词库条目里的 `$CC` / `$AA` / `$SS` 语法在特殊模式下同样有效，见[命令直通车](/docs/advanced/command-bar)。
