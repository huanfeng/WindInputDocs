两个体量很小的顶层域：输入统计 `[stats]`、日志调试 `[debug]`。

## 输入统计

```toml
[stats]
enabled = true
track_english = true
```

| 键 | 类型 | 可选值 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `enabled` | 布尔 | — | `true` | 是否统计输入字数、按键数等数据 |
| `track_english` | 布尔 | — | `true` | 是否把英文输入计入统计 |

## 宿主兼容 <Since v="0.113" /> [#host-compat]

<Callout type="warn" title="`[compat]` 顶级域已整体移除">
自 0.113 起 `config.toml` 不再有 `[compat]` 段，其唯一字段 `host_render_processes`（宿主渲染白名单）已并入 `compat.toml` 的应用规则，成为 `[[apps]]` 条目下的布尔字段 `host_render`。写在 `config.toml` 里不会有任何效果。

```toml
# 旧（0.112 及以前，config.toml）
[compat]
host_render_processes = ["SearchHost.exe"]

# 新（0.113 起，compat.toml）
[[apps]]
process = "SearchHost.exe"
comment = "Win11 开始菜单 / 任务栏搜索"
host_render = true
```

改动原因：这份白名单本来就是**按进程名匹配**的规则，与 `caret_use_top`、`initial_mode` 等同属一类，却单独躺在另一个文件里，形成了第二个真相源。合并后所有逐应用规则只有 `compat.toml` 一处。`SearchHost.exe` 已作为系统预置条目内置，无需自行添加。
</Callout>

候选框定位、光标获取、初始中英状态等**逐应用**的兼容性规则一律在 `compat.toml`（`[[apps]]` 数组表），字段清单与用法见[外观与主题 · 应用兼容性规则](/docs/customize/appearance#应用兼容性主题规则)。

## 日志调试

```toml
[debug]
log_level = "info"
log_max_size_mb = 10
log_max_files = 10
```

| 键 | 类型 | 可选值 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `log_level` | 枚举 | `trace` / `debug` / `info` / `warn` / `error` | `info` | 日志级别。留空等同 `info` |
| `log_max_size_mb` | 整数 | — | `10` | 单个日志文件的大小上限（MB），超出后滚动 |
| `log_max_files` | 整数 | — | `10` | 保留的旧日志文件数上限（不含主文件）。服务每次启动都会滚动一次，故该值约等于"能回溯最近几次运行" |

<Callout type="warn" title="修改后需重启">
`log_level` 改动后需重启输入法服务。排查问题时可临时调到 `debug` 或 `trace`，排查完调回 `info`——低级别日志量大且会拖慢输入。
</Callout>

<Callout type="info" title="日志位置">
日志文件在 `%LOCALAPPDATA%\WindInput\logs\`，见[配置文件与数据目录](/docs/advanced/config)。
</Callout>
